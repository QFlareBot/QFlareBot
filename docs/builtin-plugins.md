# 内置插件

仓库自带六个插件，写在 `apps/seed/qqbot.manifest.json` 里，部署后默认全部开启。它们大多是演示用的，也是写插件时最好的参考代码（源码在仓库的 `plugins/` 目录）。

不想要哪个，在面板「插件」页把它关掉就行，即时生效、不触发构建。面板上卸载不了内置插件；要从部署里彻底拿掉，改 `qqbot.manifest.json` 并提交。

下面的命令都以默认前缀 `/` 为例。群里 @机器人 或单聊时可以不带前缀。

## echo：回显

| 命令 | 作用 |
| --- | --- |
| `/echo <文字>` | 把文字原样回复，前面加上配置里的「回显前缀」 |
| `/proactive` | 先被动回复一条，2 秒后再主动推送一条。演示主动消息，群里要群主打开机器人的「主动消息」权限才发得出去 |

机器人被拉进群时会发一句欢迎语。部署完用 `/echo 你好` 检查机器人能不能收发消息。

## sid：查身份

`/sid`（别名 `/id`）回复你在这个机器人下的 openid、当前会话 id 与场景、你在群里的角色，以及机器人的名字和 AppID。

面板「设置 → 权限」里配 Bot 管理员名单要填 openid，先用它查。openid 按机器人隔离，从别处复制来的无效。

## multi-reply：连续回复

`/multi [条数]`（别名 `/连续`）对同一条消息连续被动回复几条，演示一条消息的多条回复。条数不填时用配置里的值，最多 5 条（平台上限）。

配置：`count` 默认条数（1–5，默认 3），`intervalMs` 每条之间的间隔（毫秒，默认 300）。

## image：发图片

`/image [图片 URL]`（别名 `/图片`、`/pic`）：不带参数时发一张内置的测试图，带 `http(s)` 地址时把那张图发出去。插件本身不下载图片，地址直接交给 QQ 去拉，所以必须是 QQ 访问得到的公网地址。

## keyboard：按键演示

`/panel`（别名 `/按钮`、`/按键`、`/button`）发一条带按键的消息，四种按键都有：发命令、填入输入框、回调、打开链接。点回调按键，机器人会回复收到的数据；「无权限」按键演示回调被拒绝时客户端的样子。

回调按键的点击记录存在插件自己的 KV 里（最多 50 条），面板侧栏「插件页面 → 按键点击记录」能看到和清空。这是[插件自带页面](./ui.md#插件页面-解耦方案)的示例。

配置：`docsUrl` 是链接按键打开的地址。

## t2i：HTML 转图片服务

没有命令。它给别的插件提供一个 `t2i` 服务：把 HTML 渲染成图片，适合做海报、排行榜这类图文消息。用法是在插件里声明 `depends: { t2i: '*' }`，再 `ctx.service('t2i')` 取出来调用（见[插件开发指南 · 要读别的插件的数据](./plugin-guide.md#要读别的插件的数据)）。

发图用 `renderUrl(html)`：图存在渲染服务上，只回一个地址，放进 `{ image: { url } }` 让 QQ 自己去拉，图片不经过 Worker。`renderBase64(html)` 要在 Worker 里把整张图编码一遍，吃的是全机器人共享的 CPU，只在拿不到地址时用。

渲染不在 Worker 里做（CPU 不够），而是调用外部的 [AstrBot T2I](https://github.com/AstrBotDevs/AstrBot) 渲染服务：

| 配置 | 说明 |
| --- | --- |
| `t2i_url` | 渲染服务地址，要支持 `POST /text2img/generate`。默认是作者部署在 Hugging Face 上的公共实例，不保证可用，量大的话自己部署一个 |
| `t2i_timeout` | 渲染超时（毫秒，5000–120000，默认 25000） |

面板侧栏「插件页面 → T2I 渲染服务」可以测试连通性、试渲染一段 HTML。
