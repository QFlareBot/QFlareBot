# 配置 QQ 开放平台

::: tip
QQ 开放平台的界面偶尔会改版，下面的菜单名以 2026-09 为准。对不上时，找名字相近的菜单即可。
:::

## 1. 在面板里创建或绑定机器人

引导部署不创建机器人，这一步在面板里做。用自定义域名打开面板，进入「设置」：

- **还没有机器人**：点「扫码创建机器人」，用手机 QQ 扫码确认即可新建，AppID 与 AppSecret 自动保存。
- **已有机器人**：填入它的 AppID 与 AppSecret 并保存。保存前 Worker 会先向 QQ 验证一次。

**必须先保存凭证再填回调地址**：凭证没保存时 Worker 不会回应平台的校验请求，平台会报校验失败。

## 2. 登录并找到机器人

打开 [q.qq.com](https://q.qq.com)，用手机 QQ 扫码登录，在应用管理里点进你的机器人。在面板里扫码新建的机器人也在这里。

进入 **开发管理**，核对这里的 AppID 和面板「设置」里的是否一致。

## 3. 填写回调地址

1. 打开 **回调配置**（也可以直接访问 <https://q.qq.com/qqbot/#/developer/webhook-setting>）。
2. 回调地址填面板概览页复制来的地址，即 `https://bot.example.com/webhook`。
3. 在 **添加事件** 里全部勾选。没有插件处理的事件，框架会直接忽略，多勾没有坏处；少勾了对应的消息就收不到。
4. 点确定保存。平台会立刻向这个地址发一次校验请求，没有提示“校验失败”就说明配好了。

不需要配置 IP 白名单。

## 4. 把机器人拉进群

回调地址校验通过后，就可以把机器人拉进**你是群主或管理员**的群：

- **群主**：一定能拉进去。
- **管理员**：有时会拉不进去，规律还没摸清。拉不进去就换一个你是群主的群。

机器人只能由它的主人拉进群，请别的群主代拉是不行的。

拉进群后，回到[快速部署 · 试一下](./deploy#_4-试一下)，在群里 @机器人 发 `/echo 你好`。

## 5. 在群里打开权限

机器人进群后默认只收得到 **@ 它的消息**，也不能主动发消息。需要的话，在群聊里点开机器人的头像，再点右上角进入权限配置：

- **获取群内全部消息**：打开后，没 @ 机器人的消息也会推给它。插件的无前缀命令（`bare: true`）要靠这个权限。
- **主动消息**：打开后，机器人可以不等别人发言、自己往群里发消息，比如定时推送。

这两个权限**只有群主能打开**。

## 沙箱与发布上线（可选）

平台上的 **沙箱配置** 和 **发布流程** 都不是必需的，个人使用可以跳过：

- **沙箱**：比较老的机器人才有这项限制，只能在沙箱里添加的群和成员中使用。
- **发布上线**：让很多人都能添加这个机器人时才需要，在平台 **首页** 的 **发布流程** 提交审核。

::: warning
目前只验证过个人使用。通过沙箱或发布上线给多人使用的场景还没有测试过。
:::

## 常见问题

**保存回调地址时提示校验失败**

- 填成了 `*.workers.dev` 的地址：QQ 访问不到，换成自定义域名。
- 域名刚绑上，证书或 DNS 还没生效：等几分钟，浏览器能打开面板后再保存。
- 面板里没有保存凭证，或者保存的 AppSecret 不是这个机器人的（比如在平台上重置过密钥）：到面板「设置」重新保存。
- 路径写错：应该是 `/webhook`。

**校验通过了，但机器人没反应**

- 事件没勾全：回到回调配置，把事件全部勾上。
- 群里没有 @机器人：群主没打开“获取群内全部消息”时，机器人只收得到 @ 它的消息，见[在群里打开权限](#_5-在群里打开权限)。
- 较老的机器人：可能还受沙箱限制，见[沙箱与发布上线](#沙箱与发布上线-可选)。
- 看面板概览页的「最近事件」：有这条消息说明回调是通的，问题出在插件；完全没有记录说明平台没推过来，回头检查上面几条。
